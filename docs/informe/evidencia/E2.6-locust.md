# E2.6 — Pruebas de carga con Locust

## Estado

La suite está implementada en `tests/performance-locust/` (escenarios de acceso y
cuestionario, objetivos y comando reproducible). **La ejecución real contra
`cg-stage` queda pendiente de realizar en el host on-prem**: desde el entorno de
desarrollo el ingress responde `503` para `stage.circleguard.local` y el túnel SSH
al host de herramientas no está disponible. No se registran métricas inventadas.

## Escenarios y objetivos

Ver `tests/performance-locust/README.md`. Resumen: p95 ≤ 500 ms en validación de
acceso, ≤ 800 ms en login, errores < 1 %, ≥ 50 req/s con 50 usuarios, 5 minutos
de estabilidad.

## Recomendaciones preliminares

- Ejecutar contra `cg-stage` con los tres ambientes desplegados; si el ingress
  devuelve `503`, verificar primero los pods del namespace (runbook §Verificar un entorno).
- El control negativo de `/api/v1/gate/validate` espera 401/403 y no cuenta como
  error; cualquier 5xx sí bloquea el objetivo de estabilidad.
- Si el p95 de login supera 800 ms, revisar la latencia del lookup a
  `identity-service` antes de ajustar el número de réplicas.
