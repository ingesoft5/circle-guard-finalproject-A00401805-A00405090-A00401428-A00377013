## 1. Trazas y logs (E2.4)

El stack versionado incluye Prometheus, Alertmanager, Grafana y Loki en
`deploy/k8s/monitoring/`; el overlay aislado `deploy/k8s/form06-dev/` añade Alloy y
Jaeger 2.23.0 con ingesta OTLP HTTP y interfaces de consulta. Los servicios publican
endpoint `/actuator/prometheus` y spans W3C/OTLP parametrizables.

### Prueba local real de Jaeger

```text

OTLP HTTP trace accepted
PASS: Jaeger returned the synthetic OTLP trace
Removed local Jaeger container
2026-11-23T00:27:40Z
```

Comando: `python3 deploy/k8s/form06-dev/smoke_traces.py`. El script levanta Jaeger
en Docker, envía un span sintético por OTLP HTTP y lo recupera por `traceID`; no
usa datos de CircleGuard y retira el contenedor. Esto prueba el protocolo y el
backend, **no** que los servicios desplegados estén exportando al Jaeger del
clúster.

No hay capturas de Grafana/Jaeger/Loki del clúster: no se enlaza una imagen que no

## 2. Compuertas de seguridad (E2.5)

`Jenkinsfile` ejecuta:

- `Trivy IaC Security Gate`: `trivy config` sobre `infra/terraform` y `deploy/k8s`,
  con conteo `CRITICAL` mediante `jq` y fallo si hay hallazgos bloqueantes.
- `Trivy Image Security Gate`: `trivy image --severity CRITICAL --ignore-unfixed --exit-code 1`
  sobre cada imagen construida en el run.
- `OWASP ZAP Security Gate`: `zap-baseline.py` en pods efímeros de `cg-stage` contra
  `auth` y `promotion`, con fallo si aparece `FAIL-NEW`.

Verificación local ejecutada sobre los manifiestos finales:

```bash
docker run --rm -v "$PWD":/work -w /work aquasec/trivy:0.70.0 \
  config --skip-version-check --severity CRITICAL --exit-code 1 deploy/k8s
# rc=0; 27 archivos configurados, 0 CRITICAL
```

Un escaneo complementario `HIGH,CRITICAL` reportó 72 `HIGH` y 0 `CRITICAL`; los
`HIGH` son guías estándar (`KSV-0014`, `KSV-0118`, `KSV-0056`) y no bloquean la
compuerta definida. Los dos `KSV-0056` corresponden al rol del deployer, que
necesita gestionar Ingress/NetworkPolicy para aplicar los overlays.

La ejecución de las compuertas de imágenes y ZAP depende de los builds y del
namespace `cg-stage`; sus resultados en Jenkins se enlazan desde el PR, no se
inventan aquí.

## 3. TLS y RBAC

Se añadió `deploy/k8s/base/rbac.yml` (`ServiceAccount`, `Role` y `RoleBinding`
`circleguard-deployer` con permisos namespace-scope) y el componente opcional
`deploy/k8s/components/tls`, expuesto como overlays `dev-tls`, `stage-tls` y
`prod-tls`. Ningún certificado o llave se guarda en el repositorio.

Render local con Kustomize v5.7.1, usando los ejemplos de secretos como entrada:

| Overlay | Documentos | Host del Ingress | `spec.tls` | Entrypoint | RBAC deployer |
|---|---:|---|---|---|---|
| `dev` | 46 | `dev.circleguard.local` | no | `web` | sí |
| `dev-tls` | 46 | `dev.circleguard.local` | `circleguard-tls` | `websecure` | sí |
| `stage` | 45 | `stage.circleguard.local` | no | `web` | sí |
| `stage-tls` | 45 | `stage.circleguard.local` | `circleguard-tls` | `websecure` | sí |
| `prod` | 46 | `prod.circleguard.local` | no | `web` | sí |
| `prod-tls` | 46 | `prod.circleguard.local` | `circleguard-tls` | `websecure` | sí |

Comandos reproducibles:

```bash
for env in dev stage prod; do
  kubectl kustomize deploy/k8s/overlays/$env > /tmp/$env.yaml
  kubectl kustomize deploy/k8s/overlays/$env-tls > /tmp/$env-tls.yaml
done
```

Pendiente en el host: crear `circleguard-tls` en cada namespace, exponer `websecure`
en Traefik, verificar `curl --resolve` con la cadena válida y migrar el kubeconfig
de Jenkins al `ServiceAccount` `circleguard-deployer`. Hasta entonces el default
sigue siendo HTTP interno, tal como declara `deploy/k8s/README.md`.
