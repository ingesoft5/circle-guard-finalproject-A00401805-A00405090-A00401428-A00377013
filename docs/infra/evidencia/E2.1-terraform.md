# E2.1 — Infraestructura como código con Terraform

Este documento recoge la evidencia local del entregable **E2.1** y la HU-INFRA-06
relacionada. La ejecución contra el host on-prem queda registrada por el usuario en
`cg-tools` según el runbook.

## 1. Alcance declarado

Terraform declara la plataforma completa con módulos reutilizables, no solo el backend:

| Módulo | Recursos gestionados |
|---|---|
| `network` | Namespace, `ResourceQuota` y `NetworkPolicy` por ambiente |
| `compute` | Clúster k3d, mirror de registro y puerto de Ingress por ambiente |
| `registry` | PVC, Deployment `registry:2` y Service `registry:5000` |
| `storage` | Buckets MinIO con versioning y PVC de aplicación |
| `observability` | Helm `kube-prometheus-stack` y `loki-stack` con alertas |

Los ambientes parametrizados están en `infra/terraform/envs/{dev,stage,prod}` y usan
`backend "s3" {}` con claves `platform/<env>/terraform.tfstate` sobre MinIO `:9002` y
DynamoDB Local `:8000` (`hash_key = "LockID"`). El bootstrap es
`infra/terraform/state-backend/`.

## 2. Validación estática ejecutada

Comandos ejecutados sobre el repositorio (sin acceso al host on-prem):

```bash
terraform fmt -check -recursive infra/terraform
# fmt_exit=0
```

Copia aislada de `infra/terraform` (sin `.terraform`) y validación de cada root/módulo
con el plugin cacheado de `infra/terraform/envs/dev/.terraform/providers`:

```bash
terraform init -backend=false -input=false -plugin-dir=<providers>
terraform validate -no-color
```

Resultado:

```text
state-backend          Success! The configuration is valid.
modules/compute        Success! The configuration is valid.
modules/network        Success! The configuration is valid.
modules/observability  Success! The configuration is valid.
modules/registry       Success! The configuration is valid.
modules/storage        Success! The configuration is valid.
envs/dev               Success! The configuration is valid.
envs/prod              Success! The configuration is valid.
envs/stage             Success! The configuration is valid.
```

## 4. Pipeline E2.3

`Jenkinsfile` incluye:

- `Terraform Plan` para `dev`, `stage` y `prod`.
- `Trivy IaC` con `trivy fs --exit-code 1 --severity CRITICAL`.
- `Terraform Apply dev`, `Terraform Apply stage` y `Terraform Apply prod`; este último detrás de `Approval prod`.
- Imagen de Jenkins con Terraform 1.9.8 y Trivy 0.58.1.
- Credentials `terraform-minio-creds` y `terraform-grafana-password`.

## 5. Pendiente en el host on-prem

El usuario debe ejecutar, en `cg-tools`:

1. Actualizar `deploy/compose/tools/.env.onpremise` con `TF_GRAFANA_ADMIN_PASSWORD`.
2. Reconstruir la imagen de Jenkins y reiniciar `cg-tools`.
3. Ejecutar el bootstrap `infra/terraform/state-backend`.
4. Ejecutar `init/validate/plan/apply` en los tres ambientes.
5. Pegar la salida de `apply` y de `plan -detailed-exitcode` (`exit=0`) para completar esta evidencia.

Hasta que esos pasos se ejecuten, este documento cubre la validación estática y la
declaración del código, no la verificación en vivo.
